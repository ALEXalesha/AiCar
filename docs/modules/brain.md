# brain.py

Сеть-водитель. Из показаний датчиков получает руль и газ.

Самый маленький модуль в проекте: две функции, около двадцати строк. При этом именно он и есть тот ИИ, который учится ездить.

## Устройство сети

```
8 входов  ->  10 нейронов (tanh)  ->  2 выхода (tanh)
```

Входы:

| Номер | Что это | Диапазон |
|---|---|---|
| 0-6 | семь лучей-датчиков, делённых на RAY_MAX | 0..1 |
| 7 | скорость, делённая на максимальную | 0..1 |

Выходы:

| Номер | Что это | Диапазон |
|---|---|---|
| 0 | руль, минус влево, плюс вправо | -1..1 |
| 1 | газ, минус это торможение | -1..1 |

Весов ровно 112: `8*10 + 10 + 10*2 + 2`.

Больше сеть ничего не знает. Ни где она на трассе, ни куда ехать, ни где финиш, ни сколько чекпоинтов взяла. Только семь расстояний до стен и своя скорость.

Этого хватает, потому что задача локальная: чтобы не врезаться и ехать по коридору, достаточно видеть коридор вокруг себя. Гоночную траекторию с оптимальным входом в поворот такая сеть не построит, но проехать круг сможет.

## Почему 10 нейронов, а не 100

Сеть учится эволюцией, а не градиентным спуском. Эволюция ищет вслепую, и стоимость поиска растёт с размерностью пространства.

112 весов это пространство, в котором генетический алгоритм с популяцией 50 находит решение за десятки поколений. Тысяча весов потребовала бы популяции в сотни и поколений в тысячи.

Кроме того, задача действительно простая. Правило "если слева близко, крути вправо" выражается парой весов. Скрытый слой из 10 нейронов нужен, чтобы сеть могла комбинировать лучи нелинейно, например притормаживать перед поворотом, а не только рулить.

## Функции

### `genome_size(n_in, hidden, n_out) -> int`

Сколько чисел в геноме. По умолчанию берёт размеры из `config.py` и возвращает 112.

Размеры не зашиты числом, а вычисляются из `N_IN`, который сам считается из числа лучей. Меняете число лучей, размер генома меняется сам, а сохранённые мозги старого размера отбрасываются проверкой длины, а не портят обучение молча.

### `forward(pop, obs, n_in, hidden, n_out) -> ndarray`

Прогон всей популяции сразу.

| Аргумент | Форма |
|---|---|
| `pop` | (N, 112) веса всех мозгов |
| `obs` | (N, 8) наблюдения всех машинок |
| результат | (N, 2) руль и газ |

Веса нарезаются из плоского генома срезами и разворачиваются в матрицы формы `(N, 8, 10)` и `(N, 10, 2)`. То есть у каждой машинки своя матрица весов, и все они лежат в одном массиве.

```python
import numpy as np
import brain

pop = np.random.default_rng(0).normal(0, 1, (50, brain.genome_size()))
obs = np.zeros((50, 8))
obs[:, 3] = 1.0            # передний луч видит далеко
print(brain.forward(pop, obs).shape)   # (50, 2)
```

## Про einsum

Ключевое место модуля:

```python
h = np.tanh(np.einsum("ni,nih->nh", obs, w1) + b1)
```

Обычное умножение матриц здесь не подходит. У каждой машинки своя матрица весов, а не одна общая на всех. Наивный вариант выглядел бы так:

```python
for i in range(N):
    h[i] = np.tanh(obs[i] @ w1[i] + b1[i])
```

Цикл на 50 итераций внутри цикла на 1800 шагов внутри цикла на 60 поколений это 5.4 миллиона проходов интерпретатора Python. Так симуляция не поедет.

Запись `"ni,nih->nh"` читается буквально: индекс `n` (машинка) есть в обоих аргументах и в результате, значит по нему идём поэлементно. Индекс `i` (вход) есть в обоих аргументах, но не в результате, значит по нему суммируем. Индекс `h` (скрытый нейрон) остаётся.

Тест `test_each_genome_uses_only_its_own_weights` проверяет ровно это: результат для машинки, посчитанный в общей пачке, совпадает с результатом, посчитанным отдельно. Ошибка в строке einsum привела бы к перемешиванию весов между машинками, и обучение выглядело бы просто плохим, без явной поломки.

## Почему на выходе tanh

Обе управляющие величины по смыслу ограничены: руль от полного влево до полного вправо, газ от полного торможения до полного газа. `tanh` даёт ровно такой диапазон.

Альтернатива без ограничения потребовала бы обрезки в физике, а сеть при этом могла бы уехать в область, где градиент по сути нулевой, и мутации перестали бы что-либо менять.

Плюс `tanh` симметричен относительно нуля, а нулевой геном даёт нулевой выход, то есть "не рулить, не газовать". Это разумное поведение по умолчанию для необученной сети, что фиксирует тест `test_zero_genome_gives_zero_output`.

## Чего в модуле нет

Нет обучения. Веса приходят снаружи готовыми, а меняет их `evolution.py`.

Нет памяти. Сеть не помнит предыдущий кадр, решение принимается только по текущим показаниям. Рекуррентность позволила бы, например, помнить, что поворот начался, но усложнила бы и сеть, и эволюцию.

Нет нормировки входов. Она делается в `race.py`, потому что там известны `RAY_MAX` и максимальная скорость конкретной машинки.

## Связи

Наблюдения собирает `race.py`, он же нормирует их и применяет выход к физике.

Веса создаёт и меняет `evolution.py`.

`stats.py` сохраняет геномы в файл, сверяя длину с `genome_size()`.
