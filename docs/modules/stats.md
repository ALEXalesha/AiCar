# stats.py

Сохранение мозгов и статистика, копящаяся между запусками игры.

Два независимых файла в папке `saves/`:

| Файл | Что внутри |
|---|---|
| `brains.npz` | популяция геномов и их приспособленность |
| `stats.json` | счётчики за всё время: раунды, финиши, рекорд |

Папка `saves/` в `.gitignore`: это результаты конкретного игрока, а не часть проекта.

## Мозги

### `save_brains(genomes, fitness, path)`

Пишет `(N, G)` геномов и `(N,)` оценок в `.npz`. Недостающие папки создаются сами.

Сохраняется вся популяция, а не только лучший геном. Так можно продолжить обучение с того же места, а не начинать с одной особи и её мутаций.

### `load_brains(path, expect)`

Возвращает пару `(genomes, fitness)` или `None`.

`None` возвращается в четырёх случаях, и каждый из них реален:

- файла нет, первый запуск
- файл побит или это вообще не `.npz`
- длина генома не совпадает с текущей сетью
- число оценок не совпадает с числом геномов

Третий случай самый коварный. Стоит поменять число лучей или размер скрытого слоя, и старый геном перестанет соответствовать сети. Без проверки numpy молча переинтерпретировал бы те же числа как другую матрицу весов, и мозг вёл бы себя как случайный, но выглядел бы загруженным.

Поэтому проверка идёт по `brain.genome_size()`, который сам считается из конфига. Меняете число лучей, старые сохранения перестают подходить автоматически.

Четвёртый случай нашёлся не рассуждением, а при проверке игры. Кнопка "сохранить", нажатая после показательного заезда, писала 50 геномов и одну оценку: приспособленность бралась у текущего заезда, а в показательном заезде участвует одна машинка. Файл получался несогласованным. Теперь игра хранит приспособленность последнего поколения отдельно, а загрузка на всякий случай сверяет длины.

### `best_brain(path, expect)`

Геном с наибольшей приспособленностью, или `None`. Именно им игра засевает популяцию при загрузке.

## Статистика

### Что копится

```python
{"rounds": 0, "finished": 0, "generations": 0, "best_time": None, "gens_to_finish": []}
```

| Ключ | Смысл |
|---|---|
| `rounds` | сыграно раундов |
| `finished` | в скольких из них кто-то доехал |
| `generations` | всего поколений обучено |
| `best_time` | лучшее время круга за всё время, секунды |
| `gens_to_finish` | за сколько поколений обучались успешные раунды |

`gens_to_finish` хранится списком, а не средним. Среднее из среднего пересчитать нельзя без числа слагаемых, а список даёт и среднее, и разброс, и историю.

### `record_round(totals, history)`

Учитывает закончившийся раунд. Возвращает **новый** словарь, исходный не трогает.

Неизменяемость здесь не для красоты. Игра держит `self.totals` и пишет его на диск; если бы функция правила словарь на месте, то любой её вызов ради проверки испортил бы состояние. Тест `test_record_round_does_not_mutate_the_original` это стережёт.

Пустая история не считается за раунд: если игрок нажал "новая трасса", не дождавшись даже первого поколения, статистику это не портит.

### `load_totals(path)` и `save_totals(totals, path)`

Загрузка устойчива ко всему: файла нет, файл побит, внутри не словарь, внутри лишние ключи. В любом из этих случаев возвращаются пустые счётчики, а не исключение.

Лишние ключи отбрасываются фильтром по `EMPTY`. Так старый файл от прежней версии игры не притащит мусор в новую.

### `summary(totals)`

Одна строка для панели:

```
всего: раундов 7, доехало 5, рекорд 11.1 с, в среднем 6.4 пок
```

## Пример

```python
import stats

totals = stats.load_totals()
totals = stats.record_round(totals, history)
stats.save_totals(totals)
print(stats.summary(totals))

stats.save_brains(brains, fitness)
genome = stats.best_brain()
```

## Связи

Проверку длины генома берёт из `brain.py`, пути из `config.py`.

`main.py` загружает счётчики при старте, дописывает раунд в момент перехода к показательному заезду и сразу пишет на диск. Кнопки "сохранить" и "загрузить" работают с мозгами.
