# train.py

Обучение водителя без графики. Поколение за поколением, пока кто-нибудь не доедет.

Модуль можно запустить сам по себе:

```
python train.py --seed 3 --generations 60
```

Видно и характерную форму обучения: долгое плато, потом резкий скачок. Так работает эволюция: она не улучшает решение понемногу, а ждёт удачной мутации, которая открывает следующий кусок трассы.

## Цикл обучения

```
поколение:
    race.run()          прогнать все 50 машинок до конца
    race.fitness()      получить 50 оценок
    запомнить лучшего
    если кто-то доехал  остановиться
    evolution.evolve()  новое поколение
```

Ничего сложного. Вся работа в модулях, которые он склеивает.

## Функции

### `build_world(rng, difficulty, width)`

Создаёт трассу, поле расстояний и машинку. Возвращает тройку.

Все три берутся из одного `rng`, поэтому один seed воспроизводит и трассу, и машинку целиком.

### `train(trk, fld, veh, brains, rng, generations, params, stop_on_finish, on_generation)`

Главная функция. Возвращает тройку:

| Значение | Смысл |
|---|---|
| `brains` | популяция после последнего поколения |
| `best` | лучший геном последнего поколения, отдельной копией |
| `history` | список `GenStats`, по одному на поколение |

`params` это словарь настроек генетического алгоритма, который передаётся в `evolution.evolve`: `elite_frac`, `mut_sigma`, `mut_rate`, `tournament_k`. Пустой словарь означает значения из `config.py`. Через него ползунки из панели попадают в обучение.

`stop_on_finish` останавливает обучение на первом финише. Для игры это правильно: цель достигнута, показывать дальше нечего. Для экспериментов есть флаг `--keep-going`, с ним обучение идёт все поколения и видно, как машинки учатся проезжать быстрее, а не просто проезжать.

`on_generation` вызывается после каждого поколения со свежей статистикой. Через него `main.py` обновляет панель, а CLI печатает строку.

`best` копируется явно через `.copy()`. Без копии это была бы строка живого массива популяции, и следующий вызов `evolve` затёр бы её на месте.

### `GenStats`

Статистика одного поколения.

| Поле | Смысл |
|---|---|
| `gen` | номер поколения с нуля |
| `best` | лучшая приспособленность |
| `mean` | средняя приспособленность |
| `alive` | сколько машинок остались живы к концу |
| `finished` | сколько доехало до финиша |
| `best_cp` | максимум взятых чекпоинтов |
| `steps` | сколько шагов длилось поколение |
| `best_time` | время лучшего финиша в секундах, 0 если никто не доехал |

`best` и `mean` вместе показывают, что происходит с популяцией. Растут оба - учится вся популяция. Растёт только лучший - нашёлся один удачный мозг, но отбор не успел его размножить. Расходятся сильно - давление отбора слишком слабое.

## Как подбирались настройки сложности

Первый же запуск показал проблему: случайный мозг из нулевого поколения проезжал всю трассу целиком. Проверка показала, что это не ошибка в чекпоинтах, машинка действительно проезжала 1952 пикселя из 2061 и брала чекпоинты равномерно каждые 12 шагов.

Значит задача была просто слишком лёгкой. Причина в форме трассы: близкая к окружности трасса решается постоянным наклоном руля, а у одного из 50 случайных мозгов такой наклон обязательно найдётся.

Замеры по 8-10 сидам:

| ширина | сложность | доехали | поколений | доехали сразу в поколении 0 |
|---|---|---|---|---|
| 90 | 0.5 | - | - | 3 из 6 |
| 90 | 1.0 | - | - | 3 из 6 |
| 60 | 1.0 | - | - | 1 из 6 |
| 45 | 0.5 | 10 из 10 | 3.0 | 4 из 10 |
| 45 | 0.8 | 10 из 10 | 3.9 | 3 из 10 |
| **45** | **1.0** | **10 из 10** | **5.2** | **0 из 10** |
| 41 | 1.0 | 8 из 10 | 16.0 | 1 из 10 |
| 36 | 1.0 | 4 из 10 | 26.2 | 0 из 10 |

Выбраны ширина 45 и сложность 1.0. Все сиды доезжают, ни один не доезжает сразу, обучение занимает около пяти поколений - есть что посмотреть, и при этом раунд не затягивается.

Главный вывод замеров: **ширина трассы влияет на сложность гораздо сильнее ползунка сложности**. Шаг с 45 на 41 роняет долю доехавших с 10/10 до 8/10 и поднимает число поколений с 5 до 16. Ползунок сложности на той же ширине двигает результат всего с 3.0 до 5.2 поколений.

Поэтому в панели именно ширина трассы работает главной ручкой сложности, хотя называется иначе. Значение по умолчанию для сложности стоит на максимуме: двигать её вниз есть смысл, чтобы раунд шёл быстрее, а чтобы усложнить, надо сужать трассу.

Заодно менялась дальность лучей. При узкой трассе с дальностью 256 все показания датчиков лежали в диапазоне 0..0.2, то есть сеть работала в узком куске своего входного диапазона. Уменьшение дальности вдвое подняло долю доехавших с 6/8 до 7/8 и вдвое ускорило расчёт датчиков.

## Производительность

0.27 секунды на поколение без графики при 50 машинках и 1800 шагах. То есть полное обучение до финиша занимает пару секунд.

Это делает возможным режим "без отрисовки" в игре: всё обучение считается быстрее, чем игрок успевает моргнуть, и остаётся только посмотреть показательный заезд.

## Связи

Склеивает `track.py`, `field.py`, `car.py`, `race.py` и `evolution.py`.

`main.py` использует `build_world` и `GenStats`, но крутит поколения сам, по шагам, чтобы рисовать кадры между шагами физики.
