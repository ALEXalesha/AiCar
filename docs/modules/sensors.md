# sensors.py

Лучи-датчики. Единственная функция: `cast`.

Это глаза машинки. Больше сеть-водитель о мире ничего не знает: ни где она на трассе, ни куда едет, ни где финиш. Только семь чисел "до стены столько-то" и своя скорость.

## Как работает

Луч не пересекается со стенами. Он идёт вперёд короткими шагами и на каждом смотрит значение поля расстояний. Первая точка, где значение стало отрицательным, и есть стена.

```
проба 1  (8 px):   +37   внутри
проба 2  (16 px):  +29   внутри
проба 3  (24 px):  +21   внутри
проба 4  (32 px):  +13   внутри
проба 5  (40 px):   +5   внутри
проба 6  (48 px):   -3   стена, ответ 48
```

Проб 32, шаг 8 пикселей, дальность 256. Если ни одна проба не ушла в минус, луч возвращает `RAY_MAX`.

Всё считается сразу для всех машинок и всех лучей. Промежуточный массив имеет форму `(машинки, лучи, пробы, 2)`, то есть для 50 машинок это `(50, 7, 32, 2)`, около 22 тысяч точек. Ни одного цикла по Python.

## Функция

### `cast(pos, angle, fld) -> ndarray`

| Аргумент | Форма | Смысл |
|---|---|---|
| `pos` | (N, 2) | позиции машинок в мире |
| `angle` | (N,) | куда смотрит нос, радианы |
| `fld` | `field.Field` | поле расстояний текущей трассы |

Возвращает `(N, 7)`: расстояние до стены по каждому лучу в пикселях.

Углы лучей заданы в `RAY_ANGLES` относительно носа: -90, -60, -30, 0, 30, 60, 90 градусов. Абсолютное направление луча это `angle + RAY_ANGLES`, отсюда сложение с broadcast по второй оси.

```python
import numpy as np
import field, sensors, track

trk = track.evolve_track(np.random.default_rng(0))
fld = field.build_for_track(trk)

pos = np.tile(trk.start_pos, (3, 1))
ang = np.full(3, trk.start_angle)
print(sensors.cast(pos, ang, fld))
# [[ 48. 56.  88. 256.  88.  56.  48.]  примерно так на старте
```

## Главная ловушка этого кода

Строчка с `np.argmax` по булеву массиву.

`np.argmax` на булевом массиве возвращает индекс первого `True`. Это ровно то, что нужно: первая проба за стеной.

Но когда `True` нет вообще, `argmax` возвращает 0, потому что все значения равны и он берёт первый. То есть луч, не увидевший ничего на всём пути, отчитается "стена на первой пробе, 8 пикселей". Машинка решит, что упёрлась носом в стену, и вывернет руль в пустоту.

Поэтому результат обязательно перекрывается отдельной маской:

```python
hit = beyond_wall.any(axis=2)
return np.where(hit, (first + 1.0) * cfg.RAY_STEP, cfg.RAY_MAX)
```

Без `np.where` код выглядит рабочим и даже проходит большинство тестов: на извилистой трассе луч почти всегда что-то видит. Ломается он на прямых участках, где передний луч уходит в даль. Тест `test_forward_ray_sees_nothing_in_a_straight_corridor` ловит именно этот случай.

## Точность и её цена

Ответ всегда кратен 8 пикселям, потому что это шаг пробы. Реальная стена может быть где угодно между двумя пробами, так что ошибка до 8 пикселей в сторону завышения.

Ошибка систематическая, а не случайная: датчик всегда показывает чуть дальше, чем на самом деле. Для управления это безопаснее наоборот было бы хуже, но сеть в любом случае подстраивается под свои датчики, какими бы они ни были. Ей важна не абсолютная точность, а повторяемость.

Уменьшение шага вдвое удваивает время расчёта датчиков, а это самая горячая часть симуляции. При ширине трассы 90 пикселей ошибка 8 пикселей это меньше десятой доли, чего достаточно.

Дальность 256 пикселей это `RAY_SAMPLES * RAY_STEP`, и константа `RAY_MAX` вычисляется именно так, а не задаётся отдельно. Если задать её больше, луч возвращал бы значение дальше, чем реально проверил.

## Что видит машинка вне трассы

Все семь лучей возвращают минимум, 8 пикселей: первая же проба оказывается за стеной, потому что за стеной уже сама машинка.

Само по себе это ничего не ломает, потому что за стеной машинка сразу помечается мёртвой и её показания больше не используются. Но тест `test_car_outside_the_track_sees_walls_at_minimum_distance` держит это поведение зафиксированным.

## Нормировка перед подачей в сеть

Сам модуль возвращает пиксели. Делением на `RAY_MAX` занимается `race.py`, там же к семи лучам добавляется восьмой вход, нормированная скорость.

Разделение сделано намеренно: датчик должен возвращать физическую величину, а как её масштабировать под конкретную сеть, решает потребитель.

## Связи
