# dataset.py

Сбор датасета для обучения генератора трасс.

Запускается отдельно, в игре не участвует:

```
python dataset.py --runs 400 --keep 5000 --min-interest 35
```

## Что такое профиль трассы

Одна строка датасета это 360 чисел от 0 до 1: радиус трассы под каждым из 360 углов, нормированный в диапазон `[R_MIN, R_MAX]`.

Хранится профиль **до сглаживания**, то есть сырой выход генератора. Это важно: `track.centerline_from_radii` сам применяет то же сглаживание, что и при генерации из CPPN, поэтому реконструкция получается точной. Если хранить сглаженную кривую, она уже не радиальна, и восстановить её радиусами нельзя.

## Откуда брать хорошие трассы

Первая попытка была самой очевидной: генерировать случайные геномы CPPN, отсеивать негодные, брать верхушку по интересу.

Замер убил эту идею. Из 200 тысяч кандидатов годными оказались 43 тысячи, но интерес у них распределён так:

| Процентиль | Интерес |
|---|---|
| 50% | 27.0 |
| 90% | 37.8 |
| 99% | 51.9 |
| 100% | 74.6 |

Эволюционные трассы дают около 57. То есть верхние 6000 случайных имели медиану 27, вдвое хуже цели. А трасс с интересом выше 40 нашлось всего 454 на 200 тысяч кандидатов: чтобы набрать 5000 таких, понадобилось бы под 2 миллиона.

### Что сработало

Урожай с самой эволюции.

`evolve_track` прогоняет 200 геномов через 15 поколений и возвращает **одного** победителя, выбрасывая тысячи промежуточных вариантов. Многие из них тоже хороши. Их и надо собирать.

`harvest_run` делает укороченную эволюцию и записывает все годные особи из поздних поколений. Первая половина поколений пропускается: там популяция ещё случайная и качество низкое.

`harvest` повторяет это много раз с независимыми стартовыми популяциями. Независимость важна: особи из одного прогона родственники и похожи друг на друга, а генеративной модели нужно разнообразие.

Итог: 400 прогонов за 284 секунды дали 5000 профилей с интересом от 40.5 до 76.8 при медиане 49.2. Против медианы 27 у случайного перебора.

## Функции

| Имя | Что делает |
|---|---|
| `normalise(radii)` | пиксели в `[0, 1]` |
| `denormalise(unit)` | обратно в пиксели |
| `judge(radii, width, difficulty)` | интерес трассы или `None`, если негодная |
| `harvest_run(...)` | один прогон эволюции, все годные особи поздних поколений |
| `harvest(runs, ...)` | много независимых прогонов |
| `collect(candidates, ...)` | старый способ: случайный перебор, оставлен для сравнения |
| `top_slice(profiles, scores, keep)` | верхушка по интересу |
| `save`, `load` | запись и чтение `.npz` |

`judge` возвращает `None`, а не ноль, чтобы негодную трассу нельзя было случайно посчитать плохой, но допустимой.

## Связи

Использует `cppn.py`, `evolution.py` и `track.py`, то есть ровно тот же код, что и обычная генерация трассы.

Результат читает `train_generator.py`. Функции нормировки использует `trackgen.py`.
