# build.py и installer.nsi

Сборка портативной версии и установщика для Windows.

```
python build.py
```

На выходе три вещи:

| Что | Размер | Для чего |
|---|---|---|
| `dist/AiCar/` | 68 МБ | готовая папка с `AiCar.exe` |
| `dist/AiCar-portable.zip` | 30 МБ | распаковал и играешь, ничего не устанавливая |
| `dist/AiCarSetup.exe` | 20 МБ | установщик с ярлыками и деинсталлятором |

Python, numpy и pygame внутрь уже упакованы, у игрока ничего ставить не надо.

## Иконка

Рисуется тем же кодом, что и машинки в игре: берётся фиксированный геном, машинка разворачивается носом вверх и кладётся на скруглённый тёмный квадрат. Pillow сохраняет результат в `.ico` со всеми размерами от 16 до 256 пикселей.

Готового файла иконки в репозитории нет намеренно: поменяется вид машинок, поменяется и иконка.

## PyInstaller

Собирается в режиме одной папки, а не одного файла. Один файл выглядит опрятнее, но при каждом запуске распаковывает 68 мегабайт во временную папку, и старт занимает секунды. Папка стартует мгновенно.

`--windowed` убирает окно консоли. Побочный эффект: `print` некуда выводить, поэтому проверка сборки сделана через ключ `--selftest`, который пишет отчёт в файл.

### Что исключено и почему

В окружении установлены torch, scipy, sklearn, pandas и другие тяжёлые библиотеки. Игре они не нужны, но PyInstaller тянет всё, до чего дотянется по импортам. Список `EXCLUDE` их отсекает, иначе сборка распухла бы до гигабайта.

Отдельная история с `setuptools`. Он тоже казался лишним, был исключён, и собранная игра падала при запуске:

```
Failed to execute script 'pyi_rth_pkgres' due to unhandled exception:
No module named 'jaraco'
```

Причина: pygame при импорте обращается к `pkg_resources` (отсюда и предупреждение о его устаревании, которое видно при обычном запуске), а `pkg_resources` тянет `jaraco`, который приехал вместе с `setuptools`. Исключив `setuptools`, я оторвал половину этой цепочки.

`setuptools` вернули в сборку, а `pkg_resources` добавили в явные импорты. Цена вопроса два мегабайта.

Мораль простая: исключать модули по названию нельзя, только по проверенному запуску собранного приложения.

## Портативная версия

Отличается от установленной ровно одним файлом: рядом с exe кладётся `portable.txt`. Пока он там, игра пишет сохранения в папку `saves` рядом с собой, а не в профиль пользователя. Установщик этот файл удаляет.

Так одна и та же сборка работает в обоих режимах, и собирать дважды не надо. Подробности в [paths.md](paths.md).

## Установщик

NSIS, скрипт `installer.nsi`.

Ставится в `%LOCALAPPDATA%\Programs\AiCar`, а не в `Program Files`. Поэтому не нужны права администратора: `RequestExecutionLevel user`. Для игры это правильный выбор, окно UAC на ровном месте раздражает.

Создаёт ярлыки в меню Пуск и на рабочем столе, прописывается в список установленных программ, кладёт рядом деинсталлятор.

При удалении спрашивает отдельно, сносить ли сохранения и статистику из `%LOCALAPPDATA%\AiCar`. По умолчанию оставляет: переустановка игры не должна стирать рекорды.

## Проверка сборки

```
dist\AiCar\AiCar.exe --selftest C:\путь\отчёт.txt
```

Игра запускается без окна, прогоняет полный раунд обучения и пишет отчёт. Мозги и статистика пишутся при этом во временную папку (`stats.use_sandbox`), так что проверка установленной игры не портит рекорды игрока:

```
запуск из архива: True
папка данных:     C:\Drive\Alexey\AiCar\dist\AiCar
модель трасс:     есть (...\_internal\models\track_vae.npz)
звук:             есть
формат звука:     44100 Гц, каналов 2 (драйвер wasapi)
трасса:           длина 1940, чекпоинтов 45
обучение:         поколений 4, состояние done
лучший результат: 4971
OK
```

Строка «лучший результат» важнее всех остальных: он совпадает с запуском из исходников до единицы. Значит сборка ничего не потеряла и не подменила, а модель трасс нашлась внутри архива. Расходиться имеют право только три первых строки, потому что у собранной версии другие пути.

Звук проверять надо с настоящим драйвером, а не с заглушкой:

```
set SDL_AUDIODRIVER=wasapi
dist\AiCar\AiCar.exe --selftest C:\путь\отчёт.txt
```

Без этого `--selftest` ставит `SDL_AUDIODRIVER=dummy`, а заглушка выдаёт любой запрошенный формат и потому не может поймать рассогласование с настоящим устройством. Ровно на этом однажды и попались (`docs/modules/sound.md`).

Проверять надо оба режима: с `portable.txt` и без него. Во втором случае в отчёте должна появиться папка профиля, и после прогона в ней должен лежать `stats.json`.
