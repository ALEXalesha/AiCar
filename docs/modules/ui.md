# ui.py

Боковая панель: ползунки, кнопки, переключатели, график.

Всё написано на прямоугольниках и событиях мыши pygame. Внешних библиотек интерфейса нет, потому что нужны четыре типа виджетов и городить ради них зависимость незачем.

## Общий договор

Каждый виджет умеет две вещи:

```python
widget.handle(event) -> bool   # событие мыши, True если что-то изменилось
widget.draw(surf, font)        # нарисовать себя
```

Виджет знает свой прямоугольник и своё значение. Он не знает, что это значение означает и кто его читает. Игра просто спрашивает `panel.value("mut_sigma")` каждый раз, когда значение нужно.

Такой опрос вместо подписки на события выбран сознательно: настроек мало, а состояние всегда согласовано, потому что источник значения ровно один - сам виджет.

## Slider

Ползунок с подписью слева и значением справа.

`integer=True` округляет и возвращает `int`. Это важно для размера популяции: он идёт в форму массива, и дробное значение уронило бы `np.zeros`.

**Захват перед перетаскиванием.** Движение мыши меняет значение только после нажатия внутри ползунка. Без этого любое движение мыши над панелью дёргало бы ползунок, над которым проходит курсор.

Область захвата чуть выше самого прямоугольника (`inflate(0, 6)`), чтобы попасть по полоске толщиной 5 пикселей было легко.

Значение всегда зажимается в `[lo, hi]` в сеттере, а не в местах вызова. Так ни один путь не может выставить значение за пределами.

Мелочь про pygame: `rect.right` это координата на один пиксель правее последнего пикселя прямоугольника, и `collidepoint` там возвращает False. Поэтому клик ровно по правому краю ползунка ничего не делает. На это уже попался тест.

## Button

Срабатывает не по нажатию, а по отпусканию внутри своей области, причём только если нажатие тоже было внутри.

Так работают кнопки везде, и не зря: нажал не туда - отвёл мышь в сторону, отпустил, ничего не случилось. Для кнопок вроде "новый раунд", которые выбрасывают текущее обучение, это заметная разница.

Результат клика хранится флагом и забирается через `take()`, который заодно сбрасывает флаг. Игровой цикл спрашивает раз за кадр:

```python
if self.ui.clicked("round"):
    self.new_round()
```

Без сброса кнопка срабатывала бы каждый кадр после единственного клика.

## Toggle

Кнопка, которая по клику переключает следующее значение из списка. Используется для скорости показа (x1, x5, x20, без отрисовки) и для выбора "мозг с нуля или продолжить".

Переключатель компактнее группы кнопок и не требует места под все варианты сразу. Минус: чтобы вернуться назад, надо прощёлкать весь круг. При двух-четырёх вариантах это не мешает.

## Graph

График лучшей и средней приспособленности по поколениям.

Масштаб по вертикали берётся от максимума, умноженного на 1.08. Запас нужен, чтобы верхняя точка не прилипала к рамке и было видно, что линия действительно достигла максимума.

Меньше двух точек рисовать нечего, и функция просто возвращается: `pygame.draw.lines` на одной точке падает.

График рисуется не в общем цикле `Panel.draw`, а отдельно, потому что ему нужны данные, а не только шрифт.

Читать его просто. Жёлтая линия это лучший в поколении, серая средний. Растут обе - учится вся популяция. Растёт только жёлтая - нашёлся один удачный мозг, но отбор не успел его размножить. Характерная форма у эволюции ступенчатая: долгое плато и резкий скачок, когда удачная мутация открывает следующий кусок трассы.

## Panel

Раскладка и диспетчер событий.

Виджеты укладываются сверху вниз курсором `cursor`. Каждый вызов `slider`, `toggle`, `buttons` или `graph` забирает у панели полосу нужной высоты и сдвигает курсор. Никаких координат вручную: чтобы вставить настройку в середину, достаточно переставить строку вызова.

`skip(n)` резервирует место под то, что панель не рисует. В игре так зарезервировано место под блок статистики сверху.

`buttons(items, per_row=2)` кладёт несколько кнопок в один ряд, деля ширину поровну с зазором. Панель шириной 300 пикселей не позволяет ставить шесть кнопок в столбик.

```python
p = ui.Panel(panel_rect, font)
p.skip(216)
p.graph("graph", 96)
p.slider("mut_sigma", "мутация", 0.01, 0.6, 0.15)
p.toggle("speed", "скорость показа", ("x1", "x5", "x20", "без отрисовки"))
p.buttons([("round", "новый раунд"), ("track", "новая трасса")])

p.handle(event)
if p.clicked("round"):
    ...
sigma = p.value("mut_sigma")
```

`handle` возвращает True, если хоть один виджет отреагировал. Обратите внимание на квадратные скобки внутри:

```python
return any([w.handle(event) for w in self.widgets.values() ...])
```

Список, а не генератор, намеренно. `any` с генератором останавливается на первом True, и остальные виджеты события не увидят. Для `MOUSEBUTTONUP` это означало бы, что ползунки не узнают об отпускании кнопки и останутся в режиме перетаскивания.

## Тесты

Проверяется логика без окна: зажатие значений в пределах, захват перед перетаскиванием, срабатывание кнопки только при отпускании внутри, одноразовость клика, цикличность переключателя, отсутствие наложений в раскладке, выход виджетов за границы панели, устойчивость графика к пустой и вырожденной истории.

Внешний вид проверяется глазами по `docs/preview_panel.png`.

## Связи

Цвета берёт из `render.py`. Оттуда же `render.fit_text` для строк, которые могут не влезть в ширину панели.

`main.py` строит панель, читает значения ползунков при каждом обращении и передаёт их в `track.evolve_track` и `evolution.evolve`.
