# paths.py

Куда класть файлы. Двадцать строк, но без них собранная игра ломается.

## Задача

Пока игра запускается из исходников, вопроса нет: и модель, и сохранения лежат в папке проекта.

После сборки в exe всё меняется. Появляются два разных места, и путать их нельзя.

| Что | Где | Права |
|---|---|---|
| модель трасс, шрифты, ассеты | внутри собранного приложения | только чтение |
| сохранения, статистика | профиль пользователя | чтение и запись |

Если писать сохранения рядом с exe, установленная в `Program Files` игра упадёт при первой же попытке сохранить: туда нельзя писать без прав администратора.

Если читать модель из профиля пользователя, её там просто не окажется.

## Три режима

```
не собрано          → всё в папке проекта
собрано, portable   → всё рядом с exe
собрано, установлено → ресурсы внутри приложения, данные в %LOCALAPPDATA%\AiCar
```

Режим portable включается файлом `portable.txt` рядом с `AiCar.exe`. Он кладётся в архив портативной версии и удаляется установщиком.

Смысл в том, что портативную версию носят на флешке, и она не должна оставлять следов на чужом компьютере. А установленная версия наоборот должна пережить переустановку самой игры, поэтому её данные лежат в профиле.

## Функции

### `frozen()`

Запущены ли мы из собранного приложения. PyInstaller выставляет `sys.frozen`.

### `resource_dir()`

Где лежат файлы только для чтения.

В собранном виде это `sys._MEIPASS`, временная папка, куда PyInstaller распаковывает содержимое. Обратите внимание: путь к ней меняется от запуска к запуску, поэтому запоминать его нельзя, надо каждый раз спрашивать.

Запасной вариант, папка рядом с exe, нужен для сборки в режиме одной папки, где `_MEIPASS` может отсутствовать.

### `data_dir()`

Где лежат файлы, в которые можно писать. Логика трёх режимов описана выше.

`LOCALAPPDATA` берётся из окружения, а не собирается вручную из имени пользователя: так работает и на нестандартно настроенной системе. Если переменной нет вообще, используется домашняя папка.

### `resource(*parts)` и `user_file(*parts)`

Склейка пути. `user_file` заодно создаёт недостающие папки, потому что при первом запуске папки сохранений ещё нет.

## Как это используется

`config.py` считает пути один раз при импорте:

```python
SAVE_DIR = os.path.join(paths.data_dir(), "saves")
BRAIN_FILE = os.path.join(SAVE_DIR, "brains.npz")
STATS_FILE = os.path.join(SAVE_DIR, "stats.json")
MODEL_FILE = paths.resource("models", "track_vae.npz")
```

Остальные модули берут пути из конфига и про существование `paths.py` не знают.

`paths.py` не импортирует `config.py`. Зависимость строго односторонняя, иначе получился бы круг.

## Проверка

Тесты подменяют `sys.frozen`, `sys.executable`, `sys._MEIPASS` и `LOCALAPPDATA`, чтобы проверить все три режима, не собирая приложение.

Собранная игра дополнительно проверяется вживую ключом `--selftest`, который печатает, какой режим определился и найдена ли модель.

## Связи

Используется только `config.py` и `main.py` (для отчёта самопроверки).
