# car.py

Генератор машинки. Из генома получается силуэт кузова и физические параметры.

Модуль отвечает только за то, какая машинка получилась. Как она едет, считает `race.py`.

## Главная мысль

Физика выводится из формы, а не задаётся отдельным случайным числом.

Площадь силуэта даёт массу. Вытянутость даёт максимальную скорость и остроту руля: длинная узкая машина быстрее, но хуже вписывается в поворот.

Смысл в связи между тем, что видно на экране, и тем, как машинка себя ведёт. Если параметры кидать независимым рандомом, круглый пузатый силуэт может оказаться самым быстрым, и это выглядит как ошибка.

## Как получается силуэт

Три шага.

**Шаг 1, форма.** CPPN рисует замкнутый контур из 24 точек с радиусами от 5 до 14 пикселей. Получается что-то вроде картофелины: где-то выпуклость, где-то впадина.

**Шаг 2, разворот.** `orient` поворачивает контур так, чтобы длинная сторона шла вдоль оси x. Иначе машинка ехала бы боком: физика считает движение вдоль своего угла, а нос был бы нарисован где попало.

**Шаг 3, растяжение.** Контур растягивается вдоль x и во столько же раз сжимается поперёк.

### Почему понадобился третий шаг

Первая версия обходилась без растяжения и брала вытянутость прямо из CPPN. Замер на 400 машинках показал, что так не работает:

```
aspect     min=1.00  med=1.12  max=2.68
max_speed  min=170    med=175   max=246
```

Медиана вытянутости 1.12 означает, что почти все машинки получались круглыми. Скорость у половины из них была 175 при возможных 260. Задуманное различие "длинная быстрая против короткой вёрткой" на практике отсутствовало.

Причина простая: контур из радиусов вокруг центра тяготеет к округлости. Чтобы радиус в одну сторону стал вдвое больше, чем в перпендикулярную, нужно редкое стечение весов.

Поэтому вытянутость взята отдельным геном. После добавления шага:

```
aspect     min=1.00  med=2.21  max=6.12  std=0.89
max_speed  min=170   med=225   max=260   std=29.1
```

### Почему растяжение сохраняет площадь

Множители по осям это `k` и `1/k`, а не `k` и `1`. Произведение равно единице, значит площадь не меняется.

Это разводит две черты машинки. Площадь отвечает за массу, растяжение за поворотливость, и они не мешают друг другу. Замер подтверждает: корреляция между вытянутостью и массой около -0.29, то есть слабая.

Если растягивать только по x, длинные машинки автоматически становились бы тяжёлыми, и два параметра слиплись бы в один. Плюс кузов вырастал бы до 73 пикселей при ширине трассы 90.

## Функции

### `polygon_area(pts) -> float`

Площадь многоугольника формулой шнурования. Модуль от результата, поэтому направление обхода не важно.

### `orient(pts) -> ndarray`

Центрирует контур и поворачивает его длинной стороной вдоль x.

Направление находится через собственные векторы матрицы `pᵀp`, то есть методом главных компонент. Собственный вектор с наибольшим собственным значением указывает направление наибольшего разброса точек.

`np.linalg.eigh` возвращает собственные значения по возрастанию, поэтому нужный вектор это последний столбец.

После поворота идёт проверка габаритов и при необходимости доворот на 90 градусов. Она нужна потому, что наибольший разброс и наибольший габарит это не одно и то же: у контура с одним длинным выступом разброс может оказаться поперёк выступа. Доворот делается через `p[:, ::-1] * [1, -1]`, что является поворотом, а не отражением, и потому не выворачивает силуэт наизнанку.

### `stretch_from(genome) -> float`

Вытянутость от 1.0 до 2.6.

Берётся сумма каждого третьего гена, начиная со второго, и прогоняется через `tanh`. Сумма, а не среднее: у суммы 22 чисел разброс в корень из 22 раз больше, и `tanh` успевает развернуться на весь диапазон. Со средним почти все машинки оказались бы около центра 1.8.

Срез `genome[1::3]` не пересекается со срезом `genome[0::3]`, который идёт на цвет. Так вытянутость и цвет получаются независимыми: одинаково красные машинки бывают и длинными, и короткими.

### `colour_from(genome) -> (r, g, b)`

Цвет через HSV. Из генома берётся только тон, насыщенность и яркость фиксированы. Так все машинки выходят одинаково яркими и различимыми на тёмном фоне, чего не будет при случайном RGB: там регулярно выпадает грязно-серый.

### `generate(genome) -> Car`

Собирает всё вместе.

```
масса        = 0.8 + 1.7 * (площадь / максимально возможная площадь)
вытянутость  = длина / ширина, обрезано в [1, 3]
скорость     = 170 + 90 * вытянутость_в_долях
руль         = 3.4 - 1.5 * вытянутость_в_долях
ускорение    = скорость * DRAG * ACCEL_FACTOR
```

Масса считается как доля от максимально возможной площади `π * CAR_R_MAX²`, а не делением на подобранное число. Первая версия делила площадь на 60, и у 400 машинок из 400 медиана массы совпала с максимумом: параметр упирался в потолок и был по сути константой. Тест `test_mass_does_not_saturate_at_the_limits` теперь это стережёт.

Вытянутость обрезается тройкой. Машинки с соотношением 4 и 6 встречаются, но ведут себя одинаково: дальше делать руль ещё тупее уже нет смысла, ездить станет невозможно.

### `random_car(rng) -> Car`

Машинка из случайного генома.

```python
import numpy as np
import car

c = car.random_car(np.random.default_rng(0))
print(c.shape.shape)       # (24, 2)
print(c.length, c.width)   # габариты кузова в пикселях
print(c.max_speed, c.max_steer, c.mass)
```

## Класс `Car`

| Поле | Смысл |
|---|---|
| `shape` | (24, 2) контур в своей системе, нос вдоль +x, центр в нуле |
| `mass` | масса |
| `accel` | ускорение при полном газе |
| `power` | мощность, `mass * accel`, только для показа в панели |
| `max_speed` | предел скорости, пикселей в секунду |
| `max_steer` | предел угловой скорости, радиан в секунду |
| `length`, `width` | габариты |
| `half_width` | половина ширины, по ней считается столкновение |
| `area` | площадь силуэта |
| `color` | цвет (r, g, b) |

`half_width` при ширине трассы 90 пикселей лежит в пределах 3-14, то есть машинка занимает от 7 до 31 процента полотна.

## Про ускорение

`accel = max_speed * DRAG * ACCEL_FACTOR` при `ACCEL_FACTOR = 1.6`.

Установившаяся скорость в модели равна `accel / DRAG`, то есть вышла бы в 1.6 раза выше предела. Ограничение сверху её обрезает, и машинка выходит на максимум примерно за секунду вместо того, чтобы бесконечно к нему подползать.

Множитель ровно единица дал бы правильный предел, но разгон занимал бы несколько секунд, и половина заезда уходила бы на набор скорости.

## Связи

Форму берёт из `cppn.py`.

`race.py` использует `accel`, `max_speed`, `max_steer` в физике и `half_width` для столкновений.

`render.py` рисует `shape`, повёрнутый на текущий угол, цветом `color`.

`ui.py` показывает `mass`, `power`, `max_speed` в панели.
