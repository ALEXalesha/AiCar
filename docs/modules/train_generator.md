# train_generator.py

Обучение VAE на профилях трасс. Единственный модуль проекта, которому нужен PyTorch.

```
python train_generator.py --epochs 400 --beta 1.0
```

В игре не участвует. Его результат это файл `models/track_vae.npz` с весами декодера, который читает `trackgen.py` обычным numpy.

## Модель

```
кодировщик:  360 -> 256 (ReLU) -> 128 (ReLU) -> mu, logvar (по 12)
декодировщик: 12 -> 128 (ReLU) -> 256 (ReLU) -> 360 (сигмоида)
```

Скрытое пространство 12-мерное. Меньше давало заметно более бедные формы, больше не улучшало результат, но замедляло сходимость.

Ошибка это сумма квадратов отклонений плюс расстояние Кульбака-Лейблера с весом `beta`. Квадраты, а не перекрёстная энтропия: радиус это непрерывная величина, а не вероятность, хотя и лежит в `[0, 1]`.

## Дополнение данных

`augment` делает две вещи с каждой партией:

- **случайный сдвиг по кругу.** Профиль периодический, поэтому `np.roll` это ровно поворот трассы. Одна трасса даёт 360 вариантов
- **отражение.** Перевёрнутый профиль это зеркальная трасса, тоже законная

Это не косметика. Без сдвигов модель выучила бы, что интересная часть трассы всегда примерно там же, где она была в датасете, потому что линия старта у всех профилей стоит в нулевом угле. Со сдвигами она вынуждена выучить форму, а не её положение.

Дополнение делается на лету, каждую эпоху заново, поэтому размер датасета на диске не растёт.

## Обучение

400 эпох на 5000 профилях, партиями по 128, Adam с шагом 1e-3. На видеокарте это 86 секунд.

Ошибка падает с 34.1 до 12.3 и дальше выходит на плато. Больше эпох ничего не добавляют.

## Проверка после обучения

Скрипт сам генерирует 200 трасс из обученной модели и считает по ним две вещи:

```
проверка: годных 60%
интерес сгенерированных: медиана 44.0, 40.0..48.0, макс 59.8
```

Это честная оценка того, что модель реально умеет, а не значение функции ошибки. Значение ошибки само по себе ничего не говорит: оно измеряет восстановление, а не качество новых трасс.

Медиана 44 против 49 у датасета показывает известное свойство VAE: он усредняет и слегка теряет разнообразие. В игре это компенсируется отбором лучшего из сорока сэмплов, что поднимает медиану до 60.

Годных 60 процентов означает, что четыре сэмпла из десяти дают непроходимую или неправильной длины трассу. Отбор в `trackgen.make_track` их отбрасывает.

## Экспорт весов

`export` берёт только слои декодера и пишет их в `.npz` как транспонированные матрицы, чтобы numpy мог считать `h @ w + b` без лишних преобразований. Кодировщик не нужен: для генерации он не используется.

Веса переводятся в float32. Файл выходит 498 килобайт против мегабайта, а разницы в результате нет: сеть маленькая, точности хватает с запасом.

## Связи

Читает датасет из `dataset.py`. Пишет веса, которые читает `trackgen.py`. Для проверки использует `track.py`.
